# XR1710G: замена загрузчика из работающей системы

[English](README.md) | **Русский**

Прошивка нового загрузчика в слот `chainloader` на XR1710G (Airoha AN7581, он
же Gemtek/Brightspeed/econet `xr1710g-ubi`) **одной командой из работающей
системы** — без UART, TFTP и кнопок. На выбор два загрузчика:

| | **http** — http-uboot | **openwrt** — chainloader OpenWrt |
| --- | --- | --- |
| Источник | [YYH2913/http-uboot](https://github.com/YYH2913/http-uboot), релиз `xr1710g_260805` | [akorshun/openwrt](https://github.com/akorshun/openwrt), релиз [`xr1710g-r7`](https://github.com/akorshun/openwrt/releases/tag/xr1710g-r7) |
| Файл | `xr1710g-chainloader-slot.bin` (uImage-шим + FIT) | `openwrt-airoha-an7581-gemtek_xr1710g-ubi-chainload-uboot.itb` (FIT) |
| Рекавери | веб-рекавери на `http://192.168.255.1` со своим DHCP, порт 10GbE | reset при включении → recovery-образ по TFTP с `192.168.1.10`; том UBI `recovery` как запасной |
| Сбой загрузки | сам уходит в веб-рекавери (`run boot_ubi \|\| http_recovery`) | грузит том `recovery`, если он есть |
| Раскладки UBI | 2.0 / 1.5 / 1.0 | только 2.0 |
| Консоль | — | меню загрузки на UART (TFTP, recovery, установщик) |

**http** — если нужно рекавери из браузера и свобода в раскладках;
**openwrt** — если на роутере OpenWrt и нужен тот же загрузчик, что идёт с
официальным образом для этой платы.

Проверено на XR1710G с iStoreOS `v1.4.0 r0+1-99598e539d` (ядро 6.18.41),
который приехал со сторонним загрузчиком `U-Boot 2026.07-xr1710g-wiro-recovery`,
и со сборками OpenWrt `xr1710g-r*` (ядро 6.18.55).

## Как это работает

Слот `chainloader` (1 МиБ по смещению `0x600000`) в системе закрыт на запись:
в `/sys/class/mtd/mtd1/flags` нет бита `MTD_WRITEABLE`, и `dd` отвечает
`Permission denied`. Штатного `kmod-mtd-rw` для таких сборок в фидах обычно
нет — модули ядра публикуются под хеш конфигурации ядра (например
`6.18.41~df820d96…`), а его никто не собирает.

Выручает то, что `vermagic` этих ядер не содержит хеша конфигурации:

```
vermagic=6.18.41 SMP mod_unload aarch64
```

Значит `mtd-rw` из **любой** upstream-сборки той же версии ядра загружается
штатно. Раскладка структур здесь тоже не страшна: `mtd-rw` обращается к
`struct mtd_info` ровно по одному смещению (`flags`, второе поле, смещение 4),
а до него нет ни одного поля, зависящего от конфигурации. Это проверяется
автоматически: `tests/check_module.py` дизассемблирует модуль и падает, если тот
полезет к другим полям. В репозитории лежат модули для ядер **6.18.41** и
**6.18.55**; скрипт сам берёт тот, что подходит к работающему ядру.

Дальше всё прямолинейно: скрипт снимает защиту, пишет слот через `mtd write`,
сверяет запись обратным чтением по sha256 и при несовпадении **сам возвращает
резервную копию**, приводит сохранённое окружение U-Boot в соответствие новому
загрузчику, выгружает модуль и перезагружает роутер.

## Прошивка

```bash
wget -O /tmp/flash.sh https://raw.githubusercontent.com/akorshun/xr1710g-uboot-recovery/main/flash.sh && sh /tmp/flash.sh
```

Сначала скрипт спросит язык (English / Русский), затем — какой загрузчик
прошить. Без вопросов:

```bash
sh /tmp/flash.sh -l ru -u openwrt -y
```

Именно в два действия и без `-q`: роутер на столе часто живёт без WAN, и тогда
`wget -qO- … | sh` молча ничего не делает — DNS не отвечает, скачивается 0 байт,
`sh` получает пустой ввод и завершается с кодом 0. Здесь ошибка будет видна.

Скрипту нужен интернет только чтобы скачать образ и, если потребуется, модуль.
Без интернета положите файлы рядом и запускайте локально — с ПК это делается так
(Git Bash, Linux, macOS):

```bash
for f in flash.sh firmware/xr1710g-chainloader-slot.bin firmware/openwrt-airoha-an7581-gemtek_xr1710g-ubi-chainload-uboot.itb firmware/mtd-rw-6.18.41.ko firmware/mtd-rw-6.18.55.ko; do ssh root@192.168.1.1 "cat > /tmp/$(basename "$f")" < "$f"; done
```

и затем на роутере `sh /tmp/flash.sh` (файлы из `/tmp` он подхватит сам).

Что делает `flash.sh`:

| Шаг | Подробности |
| --- | --- |
| язык | `-l en\|ru`, `$XR1710G_LANG` или вопрос; с `-y` — по `$LANG` (по умолчанию английский) |
| загрузчик | `-u http\|openwrt` или вопрос; с `-y` без `-u` — `http`; с `-i` — по заголовку образа |
| модель | `econet,xr1710g-ubi` из `/tmp/sysinfo/board_name` или DT |
| слот | раздел `chainloader` ровно 1 МиБ |
| текущий загрузчик | версия U-Boot (или «U-Boot OpenWrt (FIT)») из дампа слота |
| раскладка UBI | по адресу конца раздела `ubi`: 2.0 / 1.5 / 1.0 |
| образ | размер ≤ 1 МиБ; для http заголовок uImage, для openwrt FIT с U-Boot OpenWrt; sha256 по релизу; наличие HTTP-рекавери |
| только openwrt | раскладка должна быть 2.0; в томе `fit` должен лежать FIT с `config-1` (его и грузит загрузчик OpenWrt), иначе предупреждение |
| резервная копия | `/root/xr1710g-chainloader-<дата>.bin` + sha256 |
| снятие защиты | системный `kmod-mtd-rw`, иначе модуль под это ядро из репозитория со сверкой `vermagic` |
| запись | `mtd write` + обратное чтение sha256; при несовпадении — автоматический откат |
| окружение | см. ниже |
| завершение | `rmmod`, перезагрузка после подтверждения |

Опции: `-u http|openwrt` загрузчик, `-l en|ru` язык, `-i <файл>` свой образ,
`-m <файл>` свой `mtd-rw.ko`, `-r <файл>` откат на копию, `-b` ничего не писать
(только проверки, копия и подсказки), `-n` без перезагрузки, `-y` без вопросов,
`-h` справка.

Резервную копию стоит забрать на ПК:

```bash
scp root@192.168.1.1:/root/xr1710g-chainloader-*.bin .
```

### Окружение U-Boot

Оба загрузчика хранят окружение в томах UBI `ubootenv` / `ubootenv2`, и
сохранённое окружение **полностью заменяет** встроенное. Поэтому `flash.sh`:

* пустое окружение (`fw_printenv` пишет `Bad CRC`) не трогает — новый загрузчик
  возьмёт свои значения;
* окружение **другого** загрузчика (`check_buttons` → OpenWrt, `http_recovery` →
  http-uboot) **стирает** в обоих томах (`ubiupdatevol -t`), чтобы новый начал
  со своих значений по умолчанию; иначе загрузчик OpenWrt остался бы без
  обработки кнопки reset, а http-uboot — без запасного `|| http_recovery`;
* для http-uboot поверх любого другого окружения только приводит `bootcmd` к
  значению из нового образа.

## Откат

```bash
sh /tmp/flash.sh -r /root/xr1710g-chainloader-<дата>.bin
```

Тот же путь работает и для копии с ПК — просто скопируйте её обратно в `/tmp`.
Тип загрузчика определяется по самой копии, так что вернуть можно любой. Если
система уже не грузится, остаётся рекавери загрузчика, стоящего в слоте (ниже).

## Рекавери http-uboot

Адрес всегда `http://192.168.255.1`, DHCP выдаёт ПК `192.168.255.2`, кабель —
в порт 10GbE.

* **Само**: `bootcmd=run boot_ubi || http_recovery`, поэтому при неудачной
  загрузке рекавери поднимается без участия человека.
* **Кнопкой**: выключить роутер, включить и, когда замигает индикатор порта
  10GbE, нажать и держать `reset`; отпустить, когда индикатор состояния сменит
  ровный красный на «бегущий» рекавери-режим. Запас по времени большой.

Залить в него что-нибудь с ПК можно скриптами из репозитория — они сами найдут
или скачают образ, проверят sha256 и заголовок, дождутся рекавери и покажут
прогресс:

```bash
sh upload.sh                     # загрузчик http-uboot, цель uboot
```

```powershell
.\upload.ps1 -Target firmware -Layout 2.0 -File .\openwrt-...-sysupgrade.itb
```

Ручной эквивалент:

```bash
curl -X POST --data-binary @xr1710g-chainloader-slot.bin -H 'Content-Type: application/octet-stream' http://192.168.255.1/upload/uboot
```

Рекавери проверяет у цели `uboot` и magic uImage, и CRC, поэтому туда идёт
только `xr1710g-chainloader-slot.bin` — не `u-boot.bin` и не `*.itb` (включая
chainloader OpenWrt). Чтобы перейти на загрузчик OpenWrt, загрузите систему и
запустите `flash.sh -u openwrt`.

Раскладка для прошивки выбирается **по DTS заливаемого образа**, а не по текущей:

| Выбор | Раздел | Размер | Конец |
| --- | --- | --- | --- |
| UBI 2.0 | `ubi` | 439 МиБ | `0x1be00000` |
| UBI 1.5 | `ubi1.5` | 473,75 МиБ | `0x1e0c0000` |
| UBI 1.0 | `ubi1.0` | 503 МиБ | `0x1fe00000` |

Ошибка в выборе не ломает загрузчик, но Linux может бесконечно ждать
`/dev/fit0`. Заливка прошивки стирает систему, overlay, пакеты и сохранённое
окружение U-Boot; заводские MAC и EEPROM восстанавливаются из вендорного
региона DSD.

## Рекавери загрузчика OpenWrt

1. Дайте ПК адрес `192.168.1.10/24`, подключите его в порт LAN и раздайте
   TFTP-сервером `openwrt-airoha-an7581-gemtek_xr1710g-ubi-initramfs-recovery.itb`
   (из релиза [`xr1710g-r7`](https://github.com/akorshun/openwrt/releases/tag/xr1710g-r7)).
2. Включите роутер, **через 1-2 с** нажмите reset (зажатый при включении SoC
   вместо этого ждёт загрузки по UART) и держите, пока не загорится синий
   индикатор, около 15-20 с.
3. Recovery-система поднимется на `192.168.1.1`; дальше sysupgrade из неё.

Если том `fit` не загрузится, загрузчик сам загрузит том UBI `recovery`, если он
есть. На UART (115200 8N1) есть меню загрузки: загрузка по TFTP, recovery с
флеша, установщик по TFTP.

## Полезные подробности устройства

* Разделы: `vendor` 6 МиБ, `chainloader` 1 МиБ (`0x600000`), `ubi` `0x1b700000`,
  `reserved_bmt` 66 МиБ. Активного слоя ремаппинга (NMBM/BMT) нет — `reserved_bmt`
  это просто зарезервированная область, поэтому запись через `mtd` идёт напрямую.
* Тома UBI: `fit`, `ubootenv`, `ubootenv2`, `factory`, `rootfs_data` (в
  установке OpenWrt может быть ещё `recovery`).
* Слот http-uboot — это legacy-uImage-шим с корректными CRC, а по смещению
  `0x2100` лежит FIT со второй ступенью U-Boot. Chainloader OpenWrt — обычный
  FIT, который вендорный загрузчик грузит напрямую.
* `mtd write` стирает блоки только под записываемые данные, поэтому последний
  блок слота сохраняет хвост прежнего загрузчика. Для FIT это безразлично — его
  размер задан в заголовке, — и скрипт сверяет ровно столько байт, сколько в
  образе.
* Сторонний загрузчик `xr1710g-wiro-recovery` игнорирует окружение, записанное
  из Linux: сохранённый env корректен по формуле U-Boot (CRC над `data` при
  `ENV_SIZE=0x4000` с резервной копией), но эта сборка его не принимает — видимо,
  у неё другой `CONFIG_ENV_SIZE` или окружение не резервированное. Поэтому
  «перезагрузиться в рекавери через `bootcmd`» на нём не работает; у http-uboot
  для этого есть штатный `|| http_recovery`.

## Проверено

* **На железе**: `flash.sh` с http-uboot прошёл целиком на живом XR1710G —
  снятие защиты модулем (`mtd-rw: mtd0/mtd1/mtd3: setting writeable flag`,
  `mtd2` пропущен, так как уже был писабельным), запись слота, совпадение суммы
  обратного чтения, правка `bootcmd`, перезагрузка. После неё система поднялась
  сама, в слоте `U-Boot 2026.07-00766-g53b73174c0fc`, MAC-адреса и данные не
  пострадали, защита разделов вернулась (`mtd1=0x0`). Chainloader OpenWrt из
  `xr1710g-r7` записывался из Linux тем же способом (`mtd-rw` 6.18.55), его
  reset → recovery по TFTP проверен на железе; сам путь `-u openwrt` этого
  скрипта пока проверен только в CI.
* **В CI**: 134 проверки на фальшивом роутере (подменённые `/proc/mtd`,
  `/sys/class/mtd`, `/sys/class/ubi`, дамп слота, `mtd`, `insmod`,
  `fw_printenv`/`fw_setenv`, `ubiupdatevol`, `reboot`) и на мок-рекавери, под
  `dash`, `busybox sh` и `bash`, на обоих языках; отдельно shellcheck, разбор
  `upload.ps1` парсером PowerShell, проверка образа слота и обоих модулей,
  сверка обоих загрузчиков с ассетами релизов.
